# 单容器部署与完整备份

## 容器内有什么

默认 `Dockerfile` 在固定 Node.js 24.21.0 构建阶段编译后端和管理页面，运行阶段基于 NapCat 官方镜像，同时包含 Linux QQ、NapCat、Node 后端和前端产物。

NapCat 基础镜像固定到摘要 `sha256:f611790ecffa23c3c182017d5cf68179dc24612403608cd835ad13d79642f1bd`，支持上游提供的 amd64 / arm64 平台。可用 `NAPCAT_IMAGE` 构建参数明确升级，启动时不会自行下载最新版覆盖安装。

后台按实例启动 QQ 和独立虚拟显示，并提供工作目录、账号目录、端口和随机凭据。容器的主进程由 tini 管理；退出时后台先停止调度、清理自己创建的 QQ/NapCat 进程组，再释放数据锁。系统级独占锁会在强制退出后自动释放，新版残留标记可在重启时自动回收。无需额外的 Docker 守护进程、特权模式或 Docker 套接字。

## 启动与扫码

```bash
docker compose up -d --build
docker compose logs -f qqbot-fire
```

访问 `http://localhost:9988`，设置管理员密码，然后：

1. 在「NapCat 管理」填写实例名称和 QQ 号，启动实例。
2. 点击「扫码登录」，使用手机 QQ 扫码并确认。
3. 在 Bot 页面连接自动创建的 Bot，核对账号后使用。
4. 如需定时任务，先核对任务，再设置 `SCHEDULING_ENABLED=true` 并重建容器。

同容器内部的 OneBot 和 NapCat WebUI 通过回环地址访问。扫码由已鉴权的后台代理，默认只发布 `9988`，不需要另开 `3000`、`3001` 或 `6099`。添加第二个实例时使用不同的 WebUI 端口，OneBot 端口自动分配。

Bash / WSL 可以通过环境变量调整：

```bash
FIRE_BIND=0.0.0.0 FIRE_PORT=9988 SCHEDULING_ENABLED=true docker compose up -d --build
```

PowerShell 对应设置环境变量后执行同一条 Compose 命令：

```powershell
$env:FIRE_BIND = '0.0.0.0'
$env:FIRE_PORT = '9988'
$env:SCHEDULING_ENABLED = 'true'
docker compose up -d --build
```

## 持久化与日常管理

默认卷名为 `qqbot-fire-typescript-data`，挂载到 `/app/data`。它与 Java 原来的 `qqbot-fire-data` 分开。`FIRE_DATA_VOLUME` 可指定其他卷名。

| 目录或文件 | 内容 |
|---|---|
| `config.json`、`.keys/` | Bot、管理员配置与密钥 |
| `schedules*.json` | 任务与执行账本 |
| `napcat_instances.json` | 保存实例及加密的外部 WebUI 凭据 |
| `napcat-instances/<名称>/config/` | 每个实例的 NapCat、WebUI 与 OneBot 配置 |
| `napcat-instances/<名称>/home/`、`qq-profile/` | QQ 账号与客户端数据 |
| `logs/`、各实例目录 | 服务、NapCat 日志及缓存 |

```bash
docker compose stop
docker compose start
docker compose up -d --build
docker compose ps
```

`stop` 会保留卷。后台启动时自动恢复已保存的托管实例；未完成扫码的实例重新显示二维码。外部实例仅恢复登记信息，不由项目启停。

`/health` 只检查管理服务；QQ 是否登录、OneBot 是否连接分别在扫码和 Bot 页面显示，未登录不会被误报成整个容器故障。

## 完整备份

先停止服务，保证配置、账本和 QQ 数据没有并发写入。备份必须放在数据目录之外的空目录。

```bash
mkdir -p backups
docker compose stop
docker compose run --rm --no-deps --entrypoint node --volume ./backups:/backups qqbot-fire server/dist/backup-cli.js --source /app/data --destination /backups/snapshot
```

备份包含密钥、任务、账本、日志和账号二进制文件。自定义 `napCatWorkRoot` 指向数据目录外时，也会收进备份的 `backup-external/napcat-workroot/`，前提是该目录在备份容器内可访问。目录未创建也可备份。逐文件 SHA-256 与大小记录在 `backup-manifest.json`；备份目录也应按账号凭据妥善保存。

备份拒绝运行中的数据目录、未恢复事务、符号链接和特殊文件。遇到拒绝时先处理具体文件或停止相关实例，不要跳过校验强制复制。

## 恢复到新卷

保留原卷，先使用新的空卷恢复。以下为 Bash / WSL：

```bash
export FIRE_DATA_VOLUME=qqbot-fire-restored-data
docker compose run --rm --no-deps --entrypoint node --volume ./backups:/backups qqbot-fire server/dist/backup-cli.js --restore --source /backups/snapshot --destination /app/data
docker compose up -d
```

PowerShell 使用 `$env:FIRE_DATA_VOLUME = 'qqbot-fire-restored-data'` 设置新卷，其余命令相同。

恢复会先验证全部文件，不覆盖非空目标。实例工作目录自动重定位到恢复副本，原数据不被修改；NapCat 的程序安装路径仍须与部署环境匹配。管理员密码、密钥及账本随副本恢复。恢复旧快照可能丢失快照之后的发送记录，正式业务回退应使用账本合并流程，不能简单恢复旧快照后自动补发。

本机对应命令：

```bash
npm run backup:data -- --source /已停止的数据 --destination /空备份目录
npm run restore:data -- --source /备份目录 --destination /空恢复目录
```

## 外部模式与 Java 回退

仅部署新后台、连接已有 NapCat：

```bash
docker compose -f compose.typescript.yml up -d --build
```

默认预演端口为 `9989`，外部实例可在管理页面登记并扫码。WebUI Token 与 OneBot Token 用途不同，需要分别填写。

Java 回退文件为 `Dockerfile.java` 与 `compose.java.yml`。先停止新旧服务，再按「运行新服务」文档导出合并账本的最终副本。Java 容器设置 `FIRE_WEB_HOST=0.0.0.0`，本机 Java 默认仍监听回环地址；Java 入口直接在数据卷目录运行，新增任务也能持久化。
