## 单容器实测

初始环境没有 Docker 命令或套接字。本轮在独立临时目录运行隔离的 Docker Engine 28.5.2，使用 Docker Compose 5.6.0 验证。没有替换用户的 Docker 服务，也没有使用原业务数据卷。

- 默认镜像实际构建成功，内部包含 Node 后端、React 产物、Linux QQ 和 NapCat，进程以 `napcat` 用户运行。
- 同一个容器中启动了真实 Linux QQ / NapCat，后台成功取得真实二维码图片。**没有扫码登录，没有连接真实账号或发送真实消息。**
- 容器 `/health` 返回正常；管理页面、管理员鉴权、实例配置和扫码代理可用。
- 普通停止退出码为 0，耗时约 1.75 秒，没有 OOM；重启保留管理员、OneBot 凭据、任务，并自动恢复托管实例。
- 新建任务直接落入数据卷，未依赖旧入口脚本的逐文件符号链接。
- 真实实例数据共 39 个文件完成备份，校验并恢复到新卷后，管理员和任务可读取，NapCat 二维码正常。
- 默认 Compose 的桥接网络和 `127.0.0.1` 端口映射启动通过；同数据卷的第二个容器被拒绝启动。
- 强制终止容器后，新版系统锁自动释放，再次启动可恢复管理员和任务，无需删锁。
- 默认、Java 回退、轻量外部模式的 Compose 配置校验均通过。

为避免改变 WSL 的全局转发和防火墙，临时引擎禁用了 IPv4 转发及自动防火墙规则：真实 QQ 外网启动和二维码使用 host 网络验证，默认桥接模式验证了服务、端口映射、卷及崩溃恢复。正式 Docker 环境仍需具备正常外网连接；本轮没有把该临时引擎的网络限制写入项目 Compose。

镜像基础为 NapCat 官方多平台摘要 `sha256:f611790ecffa23c3c182017d5cf68179dc24612403608cd835ad13d79642f1bd`；本轮实际运行的是 amd64，arm64 未进行实际运行验证。构建时发现上游 QQ 包存在未满足的 `xdg-utils` 依赖，默认镜像已补齐该依赖。

## 回归中的修正

- NapCat 启动后立即连接导致首次失败；WebSocket 握手成功但 QQ 离线时仍尝试发送。
- 已开放端口不回应 OneBot 握手时，连接等待缺少独立超时。
- 本地 OneBot 配置与后台使用的 Token 不一致；WebUI 随机凭据和重启端口未提前落盘。
- 只看到父进程退出就遗漏仍在运行的子进程；启动器死亡后长期保留旧进程号。
- 纯文件存在性锁在强制退出后阻止重启。改为系统独占锁和版本标记；未知旧版标记仍保守拒绝自动回收；本轮在恢复预演中实际验证了该保护，确认旧容器退出后再移除其旧标记。
- Windows 隐藏窗口与独立控制台组合导致 PowerShell 锁辅助进程提前退出，已通过实际 Windows 复现并修正。
- 备份只覆盖配置而遗漏日志和账号；恢复配置仍指向原实例目录；未创建的实例目录不能恢复。

单文件回归先复现失败，再验证修复；实时日志和终端能力另通过禁用能力后的失败验证。原有发送账本、目标级幂等、未决状态和 Java 回退测试继续通过。

使用独立测试容器、数据卷和管理端口，没有导入正式任务；自动调度始终关闭。账号、好友号码、二维码、登录凭据和原始日志不写入仓库。

| 联系人读取 | 成功读取 417 位好友和 90 个群，只记录数量 |

| 应用消息回调 | 重新扫码后，隔离验证进程使用镜像中的真实 BotService 注册 EventHandler，并通过真实 WebSocket 捕获指定好友的“回调测试”；经过 EventDispatcher，未重放或伪造事件，验证结束后断开辅助连接并删除临时配置 |
| 主动断开重连 | 主动断开后重新连接，账号身份检查通过 |

| 保存凭据对照实验 | 登录服务初始化后调用 `setRemerberPwd(true)`，重新扫码立即生成 1 条历史登录记录；容器重启约 4.87 秒免扫码恢复，OneBot 和好友读取通过 |
| 正式修复镜像重建容器 | 使用正式 Dockerfile 构建镜像 `0c8ac1cde006`，停止旧测试容器，以同一数据卷新建容器；约 3.30 秒免扫码恢复，管理员与 OneBot 凭据保留，账号身份和 417 位好友读取通过 |
| 正式镜像再次重启 | 新建容器再次重启，约 4.88 秒免扫码恢复；OneBot、账号身份和好友读取通过，自动调度仍关闭，没有追加发送消息 |

本次失败的直接原因已通过对照实验确认：固定的 NapCat 4.18.37 没有在登录初始化后开启 QQ 内核的保存凭据开关，扫码后缺少可供快速登录的历史记录。镜像构建现通过 `docker/patch-napcat-login.cjs` 补齐该设置，不更改用户密码，不清理账号数据。此前已经失效的登录态需重新扫码一次；不能据此承诺 QQ 服务端永远不会撤销登录态。

再次手机扫码后登录和应用回调验证通过，没有自动重复发送测试消息。后台默认不注册消息业务处理器，辅助进程中的临时回调不代表默认开启了自动回复。测试容器使用独立引擎的 host 网络，管理服务仅监听回环地址；尚未补验真实账号在标准桥接网络下的收发。
