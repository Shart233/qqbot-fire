# QQ 扫码登录

登录管理后台后，在侧边栏打开「QQ 扫码登录」，或从 NapCat 实例卡片、NapCat 日志页面进入。页面地址为 `/#/nc-login`，支持使用 `?instance=main` 选择实例。

1. 选择需要登录的实例。已记忆但未运行的实例可在页面中启动；新实例请先到 NapCat 页面创建。
2. 用手机 QQ 的「扫一扫」扫描图片。若正在同一部手机上浏览，点击「保存二维码」，再从 QQ 扫一扫的相册中选择；也可以长按图片保存。
3. 在手机 QQ 上确认登录。页面每 2.5 秒检测一次，登录成功后隐藏二维码。

二维码失效时点击「刷新二维码」。页面会等待图片内容发生变化，避免将旧图当成刷新成功；20 秒后仍无新图会提示重试。QQ 被踢下线后若 NapCat 无法刷新，请到 NapCat 页面重启对应实例。

## 支持范围

此功能用于 QQBot Fire 启动器管理的本机 NapCat 实例，包括容器内启动的受管实例。后端读取实例工作目录下的 `cache/qrcode.png` 原始图片，并通过本机 WebUI 查询状态和请求刷新。单独运行、仅通过 OneBot 地址连接的外部 NapCat 不会出现在此列表。

登录信息和图片通过已有管理员鉴权返回，响应禁止缓存；无需开放额外公网端口。NapCat 的 WebUI 凭证仅保存在后端内存中。进程启动前遗留的旧图片不会显示，切换实例时会清除上一实例的页面状态。

NapCat WebUI 尚未就绪或认证失败时，页面会说明登录状态暂不可用，可展示本次进程生成的原始图片作为备用。若 WebUI 启用了额外认证，请通过其原生页面处理。刷新失败不会自动重启实例。

## 接口与验证

- `GET /api/napcat/instances/{name}/login`：获取状态与二维码图片。
- `POST /api/napcat/instances/{name}/login/refresh`：请求 NapCat 生成新的二维码。

修改后执行 `./gradlew compileJava`、`cd web-ui` 下的 `npm run typecheck`、`npm run lint` 和 `npm run deploy`。上线时还需验证未登录访问被拒绝、二维码刷新后图片变化、手机宽度下图片完整显示，以及实际扫码后的状态变化。
